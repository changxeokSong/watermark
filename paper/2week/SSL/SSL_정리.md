## 1. 이 논문을 읽기 전에 — 배경 지식

### 1.1 TEmIt (Transform, Embed, Inverse transform) 패러다임이란?

T. Kalker가 명명한 고전 워터마킹 프레임워크다.

```
원본 이미지
    ↓  Transform (DFT / DCT / DWT)
주파수 공간의 계수
    ↓  Embed (비밀 키에 따라 계수 수정)
수정된 계수
    ↓  Inverse Transform
워터마킹된 이미지
```

**핵심 통찰:** "지각적으로 의미 있는 계수(perceptually significant coefficient)"는 시각적 내용이 바뀌지 않는 한 변하지 않는다. → 이런 계수는 워터마크를 신뢰성 있게 담을 수 있다.

**한계:** DFT/DCT 공간은 인간이 설계한 변환 → 딥러닝 기반 특징 공간보다 표현력 제한.

---

### 1.2 Self-Supervised Learning (SSL)이란?

레이블 없이 데이터 자체에서 감독 신호를 만들어 표현을 학습하는 방법이다.

**SSL이 워터마킹에 유용한 이유 두 가지:**
1. **증강 불변성(augmentation invariance):** SSL은 동일 이미지의 다양한 변환(자르기, 색상 변환 등)에 대해 같은 특징을 출력하도록 명시적으로 훈련한다.
2. **시맨틱 붕괴 없음:** 지도 학습 분류기는 클래스 구분에 불필요한 정보를 제거한다("semantic collapse"). SSL은 클래스 레이블 없이 학습하므로 이미지의 다양한 세부 정보를 특징에 보존한다.

---

### 1.3 DINO란?

Caron et al. (ICCV 2021)이 제안한 teacher/student 방식의 SSL 방법이다.

```
student 네트워크
    ↓ (global + local crop 입력)
    출력 분포
    ↓ cross-entropy loss ↑
teacher 네트워크
    ↓ (global crop만 입력)
    출력 분포

teacher 파라미터 업데이트:
    θ_t ← λθ_t + (1 − λ)θ_s,  λ ≈ 1  (Exponential Moving Average)
```

**DINO의 특징:**
- Contrastive loss 없이 negative pair 불필요
- Local-to-global correspondence: 작은 부분 이미지(student)가 전체(teacher)의 특징을 예측
- 훈련 시 사용 증강: color jittering, Gaussian blur, solarization, resized crop, **rotation**

**왜 DINO를 선택했는가:**
- 훈련 속도 빠름
- Content-based image retrieval 성능 우수 → 특징 공간이 의미론적으로 풍부

---

### 1.4 PCA-Whitening (PCA-Sphering)이란?

DINO 특징 위에 적용하는 전처리 선형 변환이다.

**문제 상황:**
- DINO 특징들은 고차원 공간에서 특정 다양체(manifold) 위에 몰려 있음
- 워터마크는 비밀 키로 정의된 **임의의** 공간 영역 D로 특징을 이동시켜야 함
- 특징들이 D에서 멀리 떨어진 다양체 위에 있으면 이동이 어려움

**PCA-Whitening의 효과:**
```
원본 DINO 특징 x ∈ R^d  (불균일하게 분포)
         ↓ PCA-Whitening
변환된 특징 x' ∈ R^2048  (평균=0, 단위 공분산)
```

수학적으로: `x' = Λ^{-1/2} V^T (x - μ)`  
where V = 주성분 행렬, Λ = 고유값 대각 행렬, μ = 평균

결과: 특징들이 초구(hypersphere) 위에 균일하게 분포 → 워터마크 삽입이 어느 방향으로도 동일하게 어려워짐

**주의:** PCA-Whitening은 10만 개의 YFCC/COCO 이미지로 **학습**된 선형 변환 (고정된 전처리가 아님)

---

### 1.5 Hypercone(쌍 원뿔) 검출기란?

비밀 키 벡터 a를 중심축으로 하는 검출 영역이다.

```
              a (비밀 키 벡터, ||a||=1)
             /|\
            / | \
           /  |  \
          /   |θ  \
    -----/----+----\-----
          \   |   /
           \  |  /
            \ | /
             \|/

x ∈ D ⟺ |x^T a| > ||x|| cos(θ)
```

**직관:** 특징 벡터 x가 비밀 키 a와 이루는 각도가 θ보다 작으면 워터마킹된 것으로 판단.

θ는 목표 FPR(False Positive Rate)에 의해 결정된다:
```
FPR = 1 - I_{cos²θ}(1/2, (d-1)/2)
```
where I_τ(α, β)는 정규화된 불완전 베타 함수.

**쌍 원뿔인 이유:** `|x^T a|` (절댓값) → a 방향과 -a 방향 모두 워터마킹 영역으로 인정 → 마킹이 더 쉬움

---

### 1.6 Von Mises 분포란?

원형(circular) 분포의 정규분포 유사체다.

```
PDF: f(α; μ, κ) ∝ exp(κ cos(α - μ))

μ=0, κ=1일 때:
   큰 확률: α ≈ 0 (작은 회전)
   작은 확률: α ≈ ±π/2 (큰 회전)
```

논문에서의 사용: 마킹 시 회전 각도 샘플링
- 실제 환경에서 큰 회전보다 작은 회전이 더 자주 발생
- 균일 분포 대신 Von Mises 사용 → 실제 분포에 더 가까운 증강

---

### 1.7 SSIM 히트맵 감쇠란?

워터마크 신호를 지각적으로 덜 민감한 영역에 집중시키는 전처리다.

**SSIM(Structural Similarity):** 두 이미지의 구조적 유사도를 [0, 1]로 측정.

**SSIM 히트맵 생성 과정:**
```
1. 17×17 타일 단위로 원본과 워터마킹 이미지의 SSIM 계산
   (C1=0.01², C2=0.03²)
2. 각 채널별 SSIM 히트맵 합산
3. 음수값 클리핑 → 단일 히트맵 (0 이상)
```

**감쇠 적용:**
```
δ_masked = δ × (1 / SSIM_heatmap)
```
텍스처가 복잡한 영역(SSIM이 높은 곳): 더 많은 변화 허용  
균일한 영역(SSIM이 낮은 곳): 변화 억제

→ 워터마크가 텍스처 있는 영역에 집중되어 시각적으로 덜 보임 (Fig. 4의 흑백 이미지 참고)

## 2. 논문이 풀려는 문제

### 2.1 문제 정의

```
목표: 이미지에 비밀 정보를 비가시적으로 삽입하되,
     다양한 이미지 변환 후에도 복원 가능해야 함

제약 조건:
  (1) 비가시성(imperceptibility): 워터마크가 눈에 보이지 않아야 함
  (2) 페이로드(payload): k비트의 이진 메시지를 담을 수 있어야 함
  (3) 강건성(robustness): 이미지가 변형되어도 메시지를 복원할 수 있어야 함

추가 요구:
  - 블라인드 워터마킹: 디코더가 원본 이미지에 접근 불가
  - 임의 해상도에서 동작
  - 낮은 오탐율(FPR) 보장
```

### 2.2 제로비트 vs 멀티비트

| 구분 | 제로비트(Zero-bit) | 멀티비트(Multi-bit) |
|------|-------------------|-------------------|
| 목적 | 워터마크 존재 여부 탐지 | k비트 메시지 복원 |
| 비밀 키 | 단위 벡터 a ∈ R^d | 직교 벡터 집합 a₁,...,aₖ ∈ R^d |
| 탐지 영역 | 쌍 원뿔 D | 각 캐리어 기준 부호 |
| FPR 보장 | 수식으로 정확히 계산 가능 | 비트별 독립적으로 계산 |

## 3. 관련 연구 심층 분석

### 3.1 HiDDeN (Zhu et al., ECCV 2018) [ref 4]

**구조:** Encoder → [Noise Layer] → Decoder + Adversarial Discriminator

**특징:**
- 인코더-디코더를 워터마킹 목적으로 end-to-end 학습
- Noise layer: JPEG, 가우시안 블러, 드롭아웃 등 시뮬레이션
- Adversarial discriminator: 시각적 품질 향상

**왜 SSL 방법보다 부족한가:**
- 새로운 해상도나 메시지 길이마다 **재훈련 필요**
- 큰 배치 사이즈 필요 → 고해상도 이미지에서 비용 급등
- 디코딩 중심으로 설계 → 탐지(detection)에는 적합하지 않음

---

### 3.2 Vukotić et al. (WIFS 2018, Entropy 2020) [ref 22, 3]

**핵심 아이디어:** 지도 학습(ImageNet 분류)으로 훈련된 네트워크를 TEmIt의 변환기로 사용.

**워터마킹 방법:**
```
분류 네트워크 φ (역변환 없음)
      ↓
픽셀에 대한 경사 하강법으로 특징을 쌍 원뿔 안으로 "밀어 넣음"
```

**SSL 논문과의 차이:**
| 항목 | Vukotić | SSL 논문(본 논문) |
|------|---------|----------------|
| 사전 학습 | 지도 학습(레이블 필요) | 자기 지도 학습(레이블 불필요) |
| 증강 불변성 | 암묵적 | 명시적으로 훈련 |
| 마킹 시 증강 | 없음 | 있음 |
| 멀티비트 | 없음 | 있음 |

---

### 3.3 ReDMark, ROMark, Distortion Agnostic 등 [ref 5, 6, 19]

**공통 구조:** 인코더-디코더 end-to-end 학습 기반

**각 방법의 특징:**
- **ReDMark [6]:** 원형 합성곱 레이어 → 워터마크 신호를 이미지 전체에 확산
- **ROMark [5]:** Worst-case attack을 가정한 강건 최적화
- **Distortion Agnostic [19]:** 알려지지 않은 변환에 대한 적대적 훈련
- **IGA [7]:** Attention filter로 비가시성 향상

**공통 단점:**
- 임베딩 왜곡을 세밀하게 제어하기 어려움
- 탐지(detection)로 전환이 어려움 (디코딩에 최적화됨)
- SSL 논문은 이 모든 단점을 보완

## 4. 핵심 아이디어: 왜 SSL 공간이 좋은가

### 4.1 이상적인 특징 추출기의 조건

```
φ : I → F = R^d 가 만족해야 할 두 가지:

조건 1: φ(Tr(I, t)) ≈ φ(I) for all t ∈ T
        (변환에 불변 → 워터마크가 변환 후에도 유지)

조건 2: φ(I_w)를 미세한 픽셀 변화로 자유롭게 조절 가능
        (비가시적 워터마크 삽입 가능)
```

SSL 네트워크, 특히 DINO는 이 두 조건을 자연스럽게 만족한다.

### 4.2 지도 학습 vs SSL 특징 공간 비교

```
지도 학습 분류기:
  "고양이 vs 개"를 구분하는 데 필요한 특징만 보존
  → 같은 클래스의 서로 다른 이미지가 동일 특징으로 매핑될 수 있음
  → 이미지 고유 정보 손실 (semantic collapse)
  → 워터마킹에 적합하지 않음

SSL (DINO):
  레이블 없이 이미지 자체의 구조를 학습
  → 클래스 무관 세부 정보도 특징에 반영
  → 각 이미지가 고유한 특징을 가짐
  → 워터마크를 이미지에 특화시킬 수 있음
```

**Table 1의 근거:**
Rotation(25°): SSL=0.97 vs Supervised=0.54  
Blur(2.0): SSL=0.99 vs Supervised=0.04  
→ SSL 공간이 훨씬 강건한 임베딩 제공

### 4.3 "사전 훈련으로 공짜로 얻는다"의 의미

HiDDeN처럼 워터마킹용 인코더-디코더를 처음부터 학습하지 않아도 됨:

```
HiDDeN 방식:
  수백만 장 이미지 + GPU 수십 대 + 수일의 학습
  → 특정 해상도, 특정 메시지 길이에만 동작

SSL 방식:
  공개된 DINO 사전 학습 가중치 다운로드 (무료)
  + PCA-Whitening 학습 (10만 장, 수 분)
  → 임의 해상도, 임의 메시지 길이에서 동작
```

## 5. 시스템 전체 파이프라인

### 5.1 마킹(Embedding) 파이프라인

```
원본 이미지 I₀  +  [비밀 키 a (또는 캐리어 a₁...aₖ)]
        ↓
┌─────────────────────────────────────────────────────┐
│                  반복 마킹 루프 (100회)               │
│                                                     │
│  I_w ──constraints──→ I_w                           │
│      (SSIM 감쇠 + PSNR 클리핑)                       │
│                ↓                                    │
│  t ~ T 샘플 (identity/rotation/blur/crop/resize)    │
│                ↓                                    │
│       Tr(I_w, t) (증강 적용)                         │
│                ↓                                    │
│    DINO ResNet-50 φ (PCA-Whitening 포함)             │
│                ↓                                    │
│         x = φ(Tr(I_w, t))                           │
│                ↓                                    │
│   L = λL_w(x) + L_i(I_w, I₀)                       │
│                ↓                                    │
│   I_w ← I_w + η × Adam(∇L)                         │
└─────────────────────────────────────────────────────┘
        ↓ (100회 후 반올림)
워터마킹된 이미지 I_w
```

### 5.2 탐지/디코딩 파이프라인

```
수신된 이미지 I_m (변환됨)
        ↓
    DINO ResNet-50 φ + PCA-Whitening
        ↓
  특징 벡터 x ∈ R^2048

[제로비트 탐지]               [멀티비트 디코딩]
  (x^T a)² − ||x||²cos²θ > 0?    sign(x^T a₁), ..., sign(x^T aₖ)
  → 워터마킹됨 / 아님              → k비트 메시지
```

### 5.3 이 방법의 핵심 장점 정리

| 특성 | 설명 |
|------|------|
| 해상도 독립적 | φ가 임의 해상도 이미지 처리 가능 (글로벌 풀링) |
| 재훈련 불필요 | 새 메시지 길이, 새 비밀 키 → 사전 학습 그대로 사용 |
| FPR 수학적 보장 | 베타 함수로 정확히 계산 (HiDDeN은 경험적 추정만) |
| 단일 순전파 아님 | 100회 반복 경사 하강 → 느리지만 품질 제어 가능 |

## 6. 제로비트 vs 멀티비트 수식 심층 분석

### 6.1 제로비트: 쌍 원뿔 검출기

**탐지 영역:**
```
D := {x ∈ R^d : |x^T a| > ||x|| cos(θ)}
```

**강건성 추정치(robustness estimate):**
```
-L_w(x) = (x^T a)² − ||x||² cos²θ
```
- 음수: x ∉ D (탐지 실패)
- 양수: x ∈ D (탐지 성공)
- 값이 클수록 경계에서 멀리 → 더 강건

**최적성:** 점근적 가우시안 모델 하에서 이 쌍 원뿔 검출기는 최적 (Furon 2019, Merhav & Sabbag 2008)

### 6.2 멀티비트: 캐리어 투영

**메시지 인코딩:**
```
m = (m₁, ..., mₖ) ∈ {−1, +1}^k
캐리어: a₁, ..., aₖ ∈ R^d  (직교 샘플링)

워터마킹 조건: sign(x^T aᵢ) = mᵢ  for all i
```

**디코더:**
```
D(I) = [sign(φ(I)^T a₁), ..., sign(φ(I)^T aₖ)]
```

**마킹 손실 (Hinge loss with margin μ):**
```
L_w(x) = (1/k) Σᵢ max(0, μ − (x^T aᵢ)·mᵢ)
```
- margin μ=5: 경계에서 충분히 멀게 밀어 넣어 변환 후에도 sign이 유지되도록
- max(0, ...): 이미 조건을 만족한 비트는 손실에 기여 안 함

### 6.3 FPR 수식 유도 (부록 6.1 직관적 해설)

**핵심 아이디어:** 무작위 단위 벡터 U가 비밀 키 a와 이루는 각도 분포

```
U = G/||G||,  G ~ N(0, I_d)

|U^T a|² = G₁² / Σᵢ Gᵢ²

Y := (d-1) G₁² / Σᵢ₌₂ Gᵢ² ~ F(1, d-1)  (피셔 분포)

P(|U^T a| > cosθ) = 1 - I_{cos²θ}(1/2, (d-1)/2)
```

**해석:**
- d=2048일 때 FPR=10⁻⁶이 되는 θ 계산 가능
- 키 a가 균일하게 분포할 때 자연 이미지가 오탐될 확률 = FPR
- 실험 검증: YFCC 10만 장 중 오탐 0건, ImageNet 128만 장 중 오탐 1건

## 7. 마킹 알고리즘 상세

### 7.1 제약 조건(constraints) 단계

두 단계의 정규화를 픽셀 차이 δ = I_w − I₀에 적용:

**단계 1: SSIM 히트맵 감쇠**
```
δ_masked[i,j] = δ[i,j] × w[i,j]

w[i,j] ∝ SSIM_heatmap[i,j]  (텍스처 영역에서 큰 값)
```

**단계 2: PSNR 클리핑**
```
PSNR_current = 10 log₁₀(MAX² / MSE(I_w, I₀))

if PSNR_current < PSNR_target:
    δ = δ × sqrt(MSE_target / MSE_current)  (스케일 다운)
```

결과: 워터마킹된 이미지가 항상 목표 PSNR 이상 유지.

### 7.2 증강 집합 T

| 변환 | 파라미터 | 사용처 |
|------|---------|--------|
| Identity | - | Train/Mark |
| Rotation | Von Mises(μ=0, κ=1), π/2×[-1,1] | Train/Mark |
| Crop | 비율 p ~ U[0.2, 1.0] | Train/Mark |
| Resize | 스케일 p ~ U[0.2, 1.0] | Train/Mark |
| Gaussian Blur | 커널 b ~ {1,3,...,15}, σ=0.15b+0.35 | Train/Mark |
| Brightness | B | Train (Mark ✗) |
| Contrast | C | Train (Mark ✗) |
| Hue | H | Train (Mark ✗) |
| JPEG | Q | Train (Mark ✗) |
| Meme format | - | Eval only |
| Phone screenshot | - | Eval only |

**왜 Brightness/Contrast/JPEG를 마킹 시 증강에서 제외하는가:**
- 마킹 시 증강 = 경사 하강법의 목적함수에 포함됨
- JPEG은 미분 불가 → 근사 필요 (본 논문은 마킹에서 제외하고 사전 학습에서 DINO가 처리)
- Color 변환은 마킹보다 훈련 증강으로 충분히 커버 가능

### 7.3 최적화 세부 사항

```
optimizer: Adam (lr=0.01)
iterations: 100
λ = 1         (제로비트)
λ = 5 × 10⁴  (멀티비트)
μ = 5         (hinge margin)

제로비트 λ가 작은 이유: L_w 값의 스케일이 크기 때문에 균형 맞춤
멀티비트 λ가 큰 이유: k개 비트 합산 → 스케일이 작아져 큰 λ 필요
```

## 8. 손실 함수와 학습 전략

### 8.1 결합 손실 함수

```
L(I, I₀, t) = λ L_w(φ(Tr(I, t))) + L_i(I, I₀)
```

| 항 | 역할 | 상세 |
|----|------|------|
| L_w | 워터마크 임베딩 | 제로비트: 쌍 원뿔 진입 / 멀티비트: hinge loss |
| L_i | 시각적 품질 | MSE (또는 LPIPS로 대체 가능) |

**L_i의 수식:**
```
L_i(I_w, I₀) = ||I_w − I₀||² / (H × W)
```

**중요한 점:** 이 방법은 네트워크를 학습시키는 것이 아니라 **이미지 픽셀**을 최적화한다. 픽셀에 대해 역전파 가능한 이유: DINO φ와 Tr이 모두 픽셀에 대해 미분 가능.

### 8.2 Adversarial Attack과의 유사성

본 논문의 마킹 = 목적이 다른 adversarial attack:

```
Adversarial attack (FGSM 등):
  min ||δ||    s.t.  f(I + δ) ≠ y_true
  → 분류기를 속이기 위한 최소 perturbation

SSL 워터마킹:
  min L_i(I_w, I₀)    s.t.  φ(Tr(I_w, t)) ∈ D
  → 특징이 D에 들어가기 위한 최소 perturbation
```

**차이점:** 분류기를 공격하는 게 아니라, 특정 특징 공간 영역으로 끌어당기는 것.

### 9.4 멀티비트 성능: BER vs WER 분석 (Table 2)

|------|---------|---------|
| Identity | 0.1 | 0.7 |

| Crop (0.1) | **28.9** | **100** |
| Resize (0.7) | 2.1 | 29.1 |
| Blur (2.0) | **0.5** | 4.6 |

**BER과 WER의 불일치 (중요한 관찰):**
이론상 WER = 1 − (1 − BER)^k.  
예: Brightness, BER=8.7% → 이론 WER = 1-(0.913)^30 = 93.5%, 실제 WER = 60.7%.

**해석:** 이미지마다 워터마킹 난이도가 다름.
- 텍스처가 풍부한 이미지: BER 거의 0 → WER 거의 0
- 단순한 이미지(하늘, 단색 배경): BER 높음
- 전체 WER은 이 혼합으로 이론값보다 낮게 나옴

**실용적 함의:** ECC(Error Correcting Code)를 함께 사용하면 WER을 크게 낮출 수 있음.

고해상도 이미지 사용 시 BER이 대폭 낮아짐. HiDDeN은 고해상도마다 재훈련 필요 + 큰 배치 크기 불가 → 확장성 열세.

## 10. 한계점 — 어디까지인지까지

### 10.1 마킹 속도 (핵심 한계)

**문제:** 100회 경사 하강 반복 → 이미지당 수 초 ~ 수십 초 소요

**영향:** 실시간 또는 대규모 이미지 스트리밍에 적용 불가

**가능한 해결책:**
- 본 논문도 미래 과제로 언급: "네트워크를 워터마킹 목적에 맞게 추가 조정"
- 전통적 해결: amortized optimization → 인코더 네트워크를 학습해 단일 순전파로 대체
- 최신 트렌드: Stable Signature (Fernandez 2023)에서 이를 구현

### 10.2 JPEG에 대한 제한적 강건성

**문제:** 멀티비트에서 JPEG (50) BER = 20.8%, WER = 98.9%

**이유:** JPEG 미분 가능 근사를 마킹 과정에 포함하지 않음 (단지 사전 학습 DINO에 의존)

**가능한 해결책:**
- StegaStamp처럼 미분 가능한 JPEG 근사를 마킹 루프에 포함
- 단, 마킹이 더 느려질 수 있음

### 10.3 큰 Crop에 대한 취약성

**문제:** Crop (0.1), 즉 면적의 10%만 남길 때 멀티비트 WER = 100%

**이유:** 워터마크 신호가 공간적으로 분산되어 있으나, 10% 남기면 정보가 너무 적음.

**참고:** 제로비트에서는 Crop (0.1)에서도 TPR = 0.98 → 멀티비트가 더 취약

### 10.4 단색/저텍스처 이미지

**문제:** SSIM 정규화 때문에 텍스처 없는 영역에는 워터마크를 거의 못 넣음

**영향:** 하늘, 단색 배경이 주인 이미지에서 BER/WER 증가

**가능한 해결책:**
- 주파수 도메인에서의 마스킹 (JND 기반)
- 적응적 SSIM 가중치 조정

## 11. 이 논문에서 파생 가능한 연구 아이디어

### 아이디어 1: 생성 모델의 워터마킹 (Stable Signature)

**문제:** Diffusion model, GAN으로 생성된 이미지에 워터마크 삽입

**이 논문의 확장:**
- 생성 모델의 디코더(upsampling) 부분에 SSL 워터마킹 파인튜닝
- 생성 시 자동으로 워터마크 삽입 → 픽셀 최적화 불필요 → 속도 문제 해결

```
Stable Diffusion Decoder + SSL Feature Extractor 공동 파인튜닝
→ 모든 생성 이미지에 자동으로 비가시적 워터마크
```

**현황:** Fernandez et al. (2023) "The Stable Signature"에서 실제로 구현됨

---

### 아이디어 2: ViT(Vision Transformer) 기반 SSL 적용

**문제:** 본 논문은 ResNet-50 기반 DINO 사용 (2021년 기준 최신)

**확장:**
- DINO v2, MAE, EVA 등 더 강력한 ViT-based SSL 모델 적용
- 더 풍부한 특징 공간 → 더 강건한 워터마크 + 더 많은 멀티비트 페이로드

```
ResNet-50 d=2048  →  ViT-L/16 d=1024 (또는 더 크게)
캐리어 벡터 수 = d가 많을수록 더 많은 비트 가능
```

---

### 아이디어 3: Adaptive Payload (적응적 페이로드)

**문제:** 현재 모든 이미지에 동일한 k비트를 삽입

**확장:**
- 이미지 복잡도(텍스처 풍부도)를 측정
- 고복잡도 이미지: 더 많은 비트 삽입
- 저복잡도 이미지: 더 적은 비트, 더 강건하게

```
capacity_k(I) = f(texture_complexity(I))
message_length = capacity_k(I)
```

---

### 아이디어 4: 다중 워터마크 계층화

**아이디어:** 동일 이미지에 서로 다른 목적의 워터마크를 층층이 삽입

```
레이어 1 (제로비트, 강건): "이 이미지는 AI 생성"
레이어 2 (멀티비트, 약한 강건성): "생성 모델 ID + 타임스탬프"
레이어 3 (멀티비트, 취약): "사용자 ID" (재배포 추적)
```

서로 다른 비밀 키를 사용 → 각 레이어 독립 탐지 가능

### 아이디어 5: Online/Streaming 마킹

**문제:** 현재 방식은 이미지당 독립적으로 100회 반복 → 배치 처리 비효율

min_attacker  max_embedder  [Detect(Wm(I)) − Detect(Attack(Wm(I)))]

### 12.2 의료 이미지 메타데이터 임베딩

**현재 문제:** X-ray, MRI DICOM 파일은 헤더와 이미지가 분리됨 → 파일 혼동 사고

**SSL 워터마킹 적용:**
- 이미지 자체에 환자 ID, 촬영 날짜, 장비 번호를 비가시적으로 삽입
- JPEG 저장, 화면 캡처 후에도 정보 유지
- HIPAA 준수: 화면에 보이지 않으므로 환자 정보 노출 위험 낮음

**주의:** 의료 이미지의 JPEG 압축 방식이 일반과 달라 파라미터 재조정 필요

---

### 12.3 위성/드론 이미지 저작권 보호

**현재 문제:** 고가의 위성 이미지가 무단 재배포

**SSL 워터마킹 적용:**
- 이미지에 구매자 ID 삽입 (멀티비트)
- 이미지 편집(색상 조정, 자르기)에도 강건 → 재배포 추적 가능
- 고해상도에서 더 좋은 성능 → 위성 이미지에 특히 유리

---

### 12.4 박물관/미술관 디지털 아카이브

**현재 문제:** 디지털화된 예술 작품의 무단 사용

**SSL 워터마킹 적용:**
- 스캔된 작품에 기관명 + 작품 ID 삽입
- 스마트폰 촬영(물리적 재촬영)에도 강건 → StegaStamp와 유사한 활용
- 제로비트 탐지로 무단 사용 검색 엔진 구축 가능

---

### 12.5 연합 학습(Federated Learning) 데이터 출처 추적

**새로운 활용:**
- 연합 학습에 사용된 훈련 데이터 이미지에 워터마크 삽입
- 학습된 모델이 해당 워터마크를 생성하는지 확인 → 데이터 출처 증명
- 데이터 poisoning 공격 탐지에도 응용 가능

---

### 12.6 디지털 트윈 연계

**아이디어:**
- 물리적 제품 이미지에 디지털 트윈 ID 삽입
- 스마트폰 카메라로 제품 촬영 → 자동으로 디지털 트윈 조회
- QR 코드보다 자연스럽고 내구성 높음 (표면 마모 무관)

## 13. 한 줄 핵심 정리

### 논문의 핵심 기여를 3줄로

1. **SSL 특징 공간의 재발견:** 레이블 없이 사전 훈련된 DINO 네트워크가 워터마킹에 최적인 특징 공간을 "공짜로" 제공한다 — 증강 불변성이 그 핵심.

2. **마킹 시 증강의 결정적 역할:** 사전 학습에서 증강 불변성을 얻더라도 마킹 시 같은 증강을 적용해야 실제 변환에 강건하다 — "훈련-마킹 불일치"가 성능 병목.

3. **수학적으로 보장된 FPR:** 쌍 원뿔 검출기는 베타 함수로 오탐율을 정확히 계산 가능하며, 이론적으로 최적임이 증명되어 있다 — HiDDeN류의 경험적 추정과 근본적으로 다름.

### 이 논문의 패러다임

```
"사전 훈련된 SSL 네트워크는 이미 좋은 워터마킹 공간을 갖고 있다.
 인코더-디코더를 새로 학습하지 말고, 이미지를 최적화하라.
 그리고 마킹할 때 테스트 시 증강을 재현하라."
```

| 질문 | 답변 |
|------|------|
| 왜 SSL 공간이 좋은가? | 증강 불변성 명시적 학습 + semantic collapse 없음 |
| PCA-Whitening은 왜 필요한가? | DINO 특징이 다양체에 몰려 있어 임의 방향 이동이 어렵기 때문 |
| 제로비트 탐지 영역은? | 쌍 원뿔: |x^T a| > ||x||cosθ |
| FPR은 어떻게 계산하는가? | 정규화 불완전 베타 함수: 1 - I_{cos²θ}(1/2, (d-1)/2) |
| 멀티비트 디코더는? | sign(φ(I)^T aᵢ), i=1..k (각 캐리어에 투영 후 부호) |
| 마킹 최적화 방법은? | Adam (lr=0.01, 100회), 픽셀에 대한 경사 하강 |
| 증강은 어떻게 처리하는가? | Et~T[L(I, I₀, t)] — 기대값으로 손실 계산 (EoT 방식) |
| SSIM 감쇠의 역할은? | 텍스처 영역에 워터마크 집중 → 시각적 비가시성 향상 |
| 제한 해상도가 없는 이유는? | φ(ResNet-50 마지막 합성곱+글로벌 풀링)가 임의 해상도 처리 |
| 가장 큰 단점은? | 마킹 속도 (100회 반복 → 느림, 단일 순전파 아님) |
| Ours vs HiDDeN 주요 차이는? | 재훈련 불필요 + 임의 해상도 + 수학적 FPR 보장 |
